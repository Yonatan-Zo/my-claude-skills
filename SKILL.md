# Presentation

Builds slide decks for Yonatan (PhD candidate, Technion, green roofs and remote sensing) with code, so every
version is reproducible and Yonatan's corrections carry forward. The deck is generated by `scripts/build_deck.py`;
never hand-edit a pptx.

## Step 1: Ask before building (required)

A deck built on wrong assumptions about the audience or length has to be redone from scratch, so the questions
come first, before any search, file reading or design. Ask with the AskUserQuestion tool, multiple choice, 3
options each, one marked "(Recommended)" based on what you already know; Yonatan can always type a custom answer.
The tool takes at most 4 questions per call, so use two rounds.

**Round 1 — the five required questions:**

1. **Audience:** who is in the room? (e.g. scientists in Yonatan's field · mixed: utilities, councils, practitioners
   and some scientists · students or the general public)
2. **Duration and number of slides:** (e.g. 10 min, ~8 slides · 15–20 min, 13–16 slides · 30–45 min, 25–30 slides).
   Rule of thumb: about 1–1.5 minutes per slide.
3. **Colours and general design:** (e.g. light and clean, white background · dark, high contrast · Yonatan's own
   template or Technion style).
4. **Goal and main message:** what should the audience do or remember? (e.g. inspire and open discussion ·
   inform: present results clearly · persuade: support a decision or funding).
5. **Source material:** what is the deck built from? (e.g. Yonatan's files: papers, drafts, earlier decks, figures ·
   an outline Yonatan will write · research from scratch with cited literature).

**Round 2 — follow-ups to understand better (pick the 3–4 that matter most for this deck):**

- Language of the slides (English · Hebrew · both versions).
- Level of detail and numbers (big messages only · key numbers with sources · full statistics).
- Images (Yonatan's own photos and figures · open-licence photos from the web · drawn illustrations).
- Animations (click-by-click reveal · only on key slides · none).
- Branding (Technion logo on every slide · logo on title only · conference template).
- Citations on slides (small source line on every slide · references slide at the end · speaker notes only).
- Fixed parts Yonatan wants (title wording, section order, objectives, take-home messages).

**When revising an existing deck** (Yonatan asks for "v5" or changes to slides), the answers already exist: read them
from the deck's notes file (see "Project notes") and confirm them in one line instead of asking again, unless
Yonatan is changing the audience, length or design. Then go straight to Yonatan's slide-by-slide corrections.

## Step 2: Plan the structure, then wait

Write the slide-by-slide structure (section, title, key points, visual, source, speaker note, time) and show it.
Do not build the pptx until Yonatan approves the structure. A good default arc for a research talk to a mixed
audience: problem in the world → solution family → benefits with numbers → why it is not done yet → our
objectives → setup → results → future work → take-home messages.

## Step 3: Facts and sources

Yonatan's research rules apply to every number on a slide: never invent facts, search for a real source, cite
author, year, journal and DOI or link actually found. Record each fact in the project's `facts.md` with a
status (Verified = read in the source · Summary = seen only in a summary or news article · Yonatan's data). When Yonatan
asks "is this true?", answer in the chat with sources, not on a slide. Prefer fewer, solid numbers over many
weak ones.

## Step 4: Build

Use the bundled scripts as the starting point (`scripts/build_deck.py`, `scripts/prep_images.py`,
`scripts/render.ps1`): copy them into the project's `scripts/` if missing, then adapt the slide blocks. They
contain the reusable helpers: `base()` (section label, title, source line, logo, slide-number field),
`text()`, `rect()`, `pill()`, `badge()`, `picture()` (cover crop, rounded corners), `group()`, `stat_card()`,
native charts, and `animate(slide, steps)` for click-by-click fades plus a soft slide transition.

- Python: `C:\Users\yonatanz\AppData\Local\anaconda3\python.exe` (python-pptx, Pillow). No Node.
- Keep temporary images and renders outside the project, in `%TEMP%\<deck>_build\`; Yonatan likes a clean folder.
- Every version is a new file `output/<deck>_vN.pptx`. Before editing the builder, copy it to
  `scripts/build_deck_vN.py`. Never overwrite or delete earlier versions.
- For long code changes, write a small Python patch file in the scratchpad instead of a big shell heredoc.

Design defaults (adjust to Yonatan's Step 1 answers): one title per slide in a single line, few words, big visuals,
content revealed click by click (for pacing, not effects), a real slide-number field, source line on each
slide, logo on each slide, open-licence photos credited on the slide (author + licence).

## Step 5: Check

Render with `render.ps1` (PowerPoint exports every slide to PNG and reports animation counts). Look at every
new or changed slide — tile them 2 × 3 with Pillow to save effort — for text overflow, titles wrapping into
content, colliding labels, crops cutting axis labels and rotated photos. Fix and re-render until clean.

## Step 6: Save and report

Save the deck to the project's `output/` and also to the OneDrive copy of the project if one exists (Yonatan often
looks there). Then report in the chat, short and conclusion first: where the file is, what changed per slide,
what could not be done and why, what Yonatan should check, and a Sources list with links. If Yonatan asks to see the
folder, open it in File Explorer with the new file selected.

## Project notes

Each deck keeps a notes file with the Step 1 answers, Yonatan's corrections and the facts. For the green roof talk
(2026), read `references/green-roof-talk.md` and `references/facts.md` before changing anything.

## Lessons that apply to any deck

- Figures Yonatan made are raster images: their fonts cannot be enlarged on the slide. Re-plotting needs Yonatan's exact
  data and code; otherwise give Yonatan a matplotlib rcParams snippet and swap in Yonatan's re-exported figure.
- Statistics on a slide must match the figure shown (same model, same column of the table).
- Files open in Word or PowerPoint can be locked; read them with a fallback or ask Yonatan to close them.
- Wikimedia Commons rate-limits (HTTP 429): send a descriptive User-Agent, batch titles in one query, sleep
  inside Python, download 1600 px thumbnails, and look at a contact sheet before choosing (search hits are
  often wrong).
- Phone photos carry EXIF rotation: apply `ImageOps.exif_transpose`.
- python-pptx charts show an automatic title unless `chart.has_title = False`.
- Shapes added later sit on top; a semi-transparent panel can hide the title.
- Use forward slashes in paths passed from bash to PowerShell.
